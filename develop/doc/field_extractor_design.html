VLM 数据处理层

📋 功能概述

field_extractor.py 是一个字段提取模块，负责从图片中提取单个结构化字段。 它根据字段配置（名称、类型、提示词）调用 VLM 客户端获取响应，并根据字段类型进行智能解析和转换。

数据处理流程

图片 Base64
→
extract_field()
→
VLM 调用
→
类型解析
→
(value, confidence, raw)

🏗️ 架构定位

该模块在整体系统中处于中间层，承接上游图片输入，调用下游 VLM 服务：

上游：图片数据 + 字段配置 (Base64 + field_config)
当前层：field_extractor.py (字段提取逻辑)
下游：vlm_client.py (VLM API 调用)

🔄 输入输出设计

输入参数

参数名 类型 说明
image_base64 str 已编码的图片数据（含 data:image/jpeg;base64, 前缀）
field_config dict 字段元信息（名称、类型、提示词）
vlm_config dict VLM 客户端配置（endpoint, model, api_key 等）
system_prompt Optional[str] 可覆盖的默认系统提示词

输出元组

📦 返回值: tuple[Any, float, str]

  • value: 解析后的值（类型由 field_type 决定；失败返回 None）
  • confidence: 置信度（0.0 ~ 1.0，来自 VLM 或降级值）
  • raw_response: VLM 原始响应字符串（便于调试审计）

🏷️ 字段类型处理

模块支持四种字段类型，每种类型有特定的解析策略：

📝
string
直接返回
raw_response.strip()
无额外转换
🔢
number
float() 转换
支持整数/小数
失败返回 None
📋
list
json.loads() 解析
支持重试机制
失败返回 None
📦
object
json.loads() 解析
支持重试机制
失败返回 None

🔁 重试机制

针对 list 和 object 类型的 JSON 解析失败，设计了重试机制：

首次 JSON 解析
→
解析失败?
→
max_retries > 0?
→
追加提示词
"请确保输出合法JSON"
→
再次调用 VLM
→
返回结果或 None
# 重试逻辑伪代码
try:
    value = json.loads(raw_response)
except json.JSONDecodeError:
    if max_retries > 0:
        # 追强调提示词后重试
        user_prompt += "请确保输出合法JSON"
        raw_response, confidence = call_vlm(...)
        value = json.loads(raw_response)  # 再次尝试解析
    else:
        value = None

⚠️ 潜在问题

⚠️ 需要注意的问题

  • 类型注解不规范: 文档中写的是 dict[str, any]，应为 dict[str, Any]
  • 置信度来源不明确: 降级策略未定义（默认值？何时触发？）
  • 重试边界情况: max_retries=0 时重试被跳过，需在配置中明确
  • 错误处理不一致: JSON 解析失败返回 None，但 VLM 异常处理策略未明确

💡 改进建议

✅ 推荐改进

  • 定义错误类型: 创建 ExtractionError 异常类，统一错误处理
  • 字段配置验证: 添加 validate_field_config() 函数
  • 结构化返回: 使用 @dataclass 定义 ExtractionResult
  • 日志增强: 添加字段名、解析耗时等上下文信息
from dataclasses import dataclass
from typing import Any, Optional

@dataclass
class ExtractionResult:
    value: Any
    confidence: float
    raw_response: str
    field_name: str
    success: bool
    error_message: Optional[str] = None

class ExtractionError(Exception):
    """字段提取失败"""
    def __init__(self, field_name: str, cause: str):
        self.field_name = field_name
        self.cause = cause

📊 总结

✅ 设计亮点

  • 职责单一：专注于单个字段提取，不涉及聚合逻辑
  • 类型化处理：四种类型各有策略，清晰可控
  • 调试友好：保留原始响应，便于问题追踪
  • 容错设计：JSON 解析失败有重试机制
