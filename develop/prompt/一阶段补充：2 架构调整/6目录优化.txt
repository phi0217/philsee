目录结构优化建议：philsee 通用文档解析系统

一、当前目录结构问题分析

1. online/ 目录下模块文件散乱，缺乏功能分层
2. develop/script/一阶段/ 与 online/ 存在重复代码，容易混淆
3. 缺少明确的分层架构（models、schemas、repositories 等）
4. 配置文件分散，缺少统一的配置管理目录
5. tests/ 目录结构过于简单，未按模块组织

三、分层职责说明

1. api/ 层
   - 负责接收 HTTP 请求、参数校验、响应格式化
   - 不包含业务逻辑，仅调用 service 层
   - 通过 deps.py 实现依赖注入

2. services/ 层
   - 核心业务逻辑所在
   - 协调多个 repository、processor 完成业务流程
   - 处理事务边界

3. models/ 层
   - SQLAlchemy ORM 模型定义
   - 与数据库表一一对应

4. schemas/ 层
   - Pydantic 模型定义
   - 用于请求验证和响应序列化
   - 与 API 接口契约对应

5. repositories/ 层
   - 封装数据库操作
   - 提供 CRUD 方法
   - 隔离 SQL 细节

6. processors/ 层
   - 文档处理管道的各个阶段
   - 可独立测试、可组合

四、迁移步骤

第一步：创建新目录结构
mkdir -p online/{api,services,models,schemas,repositories,core,processors}
mkdir -p tests/{unit,integration,fixtures}

第二步：迁移核心文件
- main_api.py → online/main.py
- config_loader.py → online/services/config_service.py
- vlm_client.py → online/core/vlm_client.py
- minio_upload.py → online/services/storage_service.py

第三步：创建模型层
- 从 init_db.sql 反向生成 SQLAlchemy 模型
- 或手动定义 models/*.py

第四步：创建 Schema 层
- 根据接口文档定义请求/响应 Schema

第五步：重构 API 层
- 将路由逻辑拆分到 api/routers/

第六步：更新测试目录
- 按 unit/integration 分类组织测试

六、依赖注入示例

online/api/deps.py:

```python
from functools import lru_cache
from typing import AsyncGenerator

from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine
from sqlalchemy.orm import sessionmaker

from config.settings import settings

engine = create_async_engine(settings.database_url, echo=settings.debug)
AsyncSessionLocal = sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

async def get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as session:
        yield session

@lru_cache
def get_vlm_client():
    from online.core.vlm_client import VLMClient
    return VLMClient(settings.vlm_api_key, settings.vlm_base_url)
```

七、配置管理示例

config/settings.py:

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    # 数据库
    database_url: str

    # VLM
    vlm_api_key: str
    vlm_base_url: str

    # MinIO
    minio_endpoint: str
    minio_access_key: str
    minio_secret_key: str
    minio_bucket: str

    # 应用
    debug: bool = False
    app_name: str = "Philsee Document Parser"

    class Config:
        env_file = ".env"

settings = Settings()
```

八、优化收益

1. 清晰的分层架构，降低耦合度
2. 便于单元测试（每层可独立 mock）
3. 代码职责明确，新人易于上手
4. 符合 FastAPI 最佳实践
5. 为后续微服务化预留空间
