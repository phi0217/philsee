项目改造提示词：配置模板化 + 分流决策追踪（删库重建，无外键约束）
当前系统已完成基础功能，但配置管理存在局限，需要升级为模板化配置，并支持按权重分流。同时要求在 requests 表中增加 trace 字段，记录详细的分流决策过程，便于调试和 A/B 测试分析。

改造方式：直接删除现有数据库并重建（不提供迁移脚本），使用全新的表结构。所有旧数据丢失，开发阶段可接受。

删除旧表（如果存在）

创建新表：config_versions（无 is_active）、config_templates、requests（增加字段）、field_extractions、agg_decisions

插入初始配置示例（可选）

sql
-- 删除旧表（顺序重要，先删有外键依赖的）
DROP TABLE IF EXISTS agg_decisions;
DROP TABLE IF EXISTS field_extractions;
DROP TABLE IF EXISTS requests;
DROP TABLE IF EXISTS config_templates;
DROP TABLE IF EXISTS config_versions;

-- ==================== 配置版本表 ====================
CREATE TABLE config_versions (
    id INT PRIMARY KEY AUTO_INCREMENT,
    version_tag VARCHAR(64) NOT NULL COMMENT '版本标识，如 v1.0.0',
    doc_type VARCHAR(64) NOT NULL COMMENT 'fields 时固定为 *；profile/aggregation 时为具体文档类型',
    config_type ENUM('fields','profile','aggregation') NOT NULL,
    content JSON NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    created_by VARCHAR(64),
    is_deleted BOOLEAN DEFAULT FALSE,
    UNIQUE KEY uk_unique (doc_type, config_type, version_tag)
);

-- ==================== 配置模板表 ====================
CREATE TABLE config_templates (
    id INT PRIMARY KEY AUTO_INCREMENT,
    template_id VARCHAR(64) NOT NULL COMMENT '模板编号，如 invoice_extraction',
    version VARCHAR(32) NOT NULL COMMENT '模板版本，如 v1.0.0',
    doc_type VARCHAR(64) NOT NULL COMMENT '适用的文档类型，如 invoice',
    description TEXT COMMENT '模板说明',
    fields_config_id INT NOT NULL COMMENT '关联 config_versions.id (config_type=fields)',
    profile_config_id INT NOT NULL COMMENT '关联 config_versions.id (config_type=profile)',
    aggregation_config_id INT NOT NULL COMMENT '关联 config_versions.id (config_type=aggregation)',
    is_active BOOLEAN DEFAULT TRUE COMMENT '是否启用',
    weight INT NOT NULL DEFAULT 0 COMMENT '分流权重（0-100），同一 template_id 下所有 is_active=1 的版本权重和应为 100',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    created_by VARCHAR(64),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    updated_by VARCHAR(64),
    UNIQUE KEY uk_template_version (template_id, version),
    KEY idx_doc_type (doc_type),
    KEY idx_active (template_id, is_active)
);

-- ==================== 请求主表（增加字段） ====================
CREATE TABLE requests (
    trace_id VARCHAR(64) PRIMARY KEY,
    doc_type VARCHAR(64) NOT NULL,
    total_pages INT,
    final_fields JSON,
    warnings JSON,
    template_id VARCHAR(64) COMMENT '实际使用的模板编号',
    template_version VARCHAR(32) COMMENT '实际使用的模板版本',
    selected_weight INT COMMENT '命中模板版本的权重',
    trace JSON COMMENT '分流决策详细记录',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- ==================== 字段提取明细表 ====================
CREATE TABLE field_extractions (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    trace_id VARCHAR(64) NOT NULL,
    page_num INT NOT NULL,
    field_name VARCHAR(64) NOT NULL,
    extracted_value TEXT,
    confidence FLOAT,
    raw_response TEXT,
    minio_path VARCHAR(255),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX(trace_id, page_num)
);

-- ==================== 聚合决策表 ====================
CREATE TABLE agg_decisions (
    trace_id VARCHAR(64) NOT NULL,
    field_name VARCHAR(64) NOT NULL,
    selected_page INT,
    selected_value TEXT,
    reason VARCHAR(255),
    candidates JSON,
    PRIMARY KEY(trace_id, field_name)
);

async def load_config(doc_type: str = None, template_id: str = None):
    template, trace = await resolve_template(doc_type, template_id)
    fields = await get_config_by_id(template['fields_config_id'])
    profile = await get_config_by_id(template['profile_config_id'])
    agg = await get_config_by_id(template['aggregation_config_id'])

5. 请求兼容处理
由于旧客户端可能只传 doc_type，需要在系统中维护一个 doc_type 到默认 template_id 的映射。建议通过配置文件（如 settings.yaml）或环境变量设置：

yaml
default_templates:
  invoice: "invoice_extraction_v1"
  letter_of_credit: "lc_extraction_v1"
在 resolve_template 中实现此映射逻辑。

三、注意事项
不添加外键约束，应用层需保证 fields_config_id 等指向存在的 config_versions.id。

删除 is_active 后，所有配置版本均为历史，只有被模板引用的版本才会被使用。

权重和校验：建议在模板保存时进行前端校验，后端保存时也应检查并记录警告，但不强制拒绝。

所有数据库操作使用异步 SQLAlchemy 或 aiomysql，注意事务。
