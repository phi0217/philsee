四、每张表的详细要求
1. config_templates（配置模板表）
作用：存储配置组合（fields + profile + aggregation）的模板，支持多版本按权重分流。

字段：必须包含 id, template_id, version, doc_type, description, fields_config_id, profile_config_id, aggregation_config_id, is_active, weight, created_at, created_by, updated_at, updated_by, pre_process（管道符分隔的前处理序列）。

特别说明：

fields_config_id 等引用 config_versions.id，但无外键约束，由应用层保证完整性。

pre_process：字符串，格式如 "fix_orientation|deskew|scale(1024)"，用于对整页图片进行预处理。

同一 template_id 下可存在多个 is_active=1 的版本，系统根据 weight 随机分流。权重和应为 100，但不在数据库层强制，由应用层校验。

索引：包含 uk_template_version (template_id, version)、idx_doc_type (doc_type)、idx_active (template_id, is_active)。

示例：展示一个模板记录，包含 pre_process 和合理的字段引用。

2. requests（请求主表）
作用：记录每次解析请求的总体信息，包括最终提取结果、使用的模板、分流决策痕迹。

字段：trace_id (PK), doc_type, total_pages, final_fields (JSON), warnings (JSON), template_id, template_version, selected_weight, trace (JSON), created_at。

特别说明：

trace 字段存储分流决策详情，JSON 结构应包含 candidates（候选模板列表）、random_value、selected_index、decision、fallback_used 等。

final_fields 存储聚合后的最终字段值，格式与 fields 配置对应。

索引：主键 trace_id，可考虑为 created_at 加索引用于范围查询（可选）。

示例：展示一条完整请求记录，含 trace 示例。

3. field_extractions（字段提取明细表）
作用：记录每页每个字段的原始提取结果，用于调试、复审和自优化。

字段：id (PK, AUTO_INCREMENT), trace_id (关联 requests.trace_id), page_num, field_name, extracted_value (TEXT), confidence (FLOAT), raw_response (TEXT), minio_path (VARCHAR), created_at。

特别说明：

raw_response 存储 VLM 返回的原始文本（未解析），是分析错误的关键数据。

extracted_value 是经过类型转换后的值（如数字、列表 JSON 字符串），便于直接使用。

minio_path 存储该页图片在 MinIO 中的路径，便于追溯。

索引：(trace_id, page_num) 组合索引，因为查询通常按请求和页码过滤。

示例：展示某个字段的提取记录。

4. agg_decisions（聚合决策表）
作用：记录每个字段的跨页聚合决策过程，用于审计和调试聚合逻辑。

字段：trace_id, field_name (复合主键), selected_page (INT), selected_value (TEXT), reason (VARCHAR), candidates (JSON)。

特别说明：

reason 常见取值：first_non_null, last_non_null, max_confidence, merge_lists, first_non_null_all_none 等。

candidates 存储 JSON 数组，每个元素包含 page, value, confidence。

索引：主键 (trace_id, field_name)，无需额外索引。

示例：展示一个 max_confidence 决策的候选列表。
